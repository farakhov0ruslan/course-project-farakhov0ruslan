# ADR: Структурированный безопасный логер с correlation_id и маскированием PII

* **Статус:** Accepted
* **Дата:** 2025-10-22
* **Компонент:** API / Logging
* **Связанные NFR:** NFR-03 (политика PII в логах)
* **Артефакты реализации:**

  * `utils_library/logger.py` — реализация логера/форматтера
  * Интеграция в `app/main.py` (инициализация)
  * Вызовы логера в `app/routers/notes.py` и `app/routers/tags.py`
  * Тесты: `tests/test_logger.py` (маскирование PII, reserved keys, JSON-форма)

## Контекст

* По NFR-03 запрещено логировать содержимое заметок/секреты;
* Стандартный `logging` Python не позволяет передавать в `extra` ключи, совпадающие с атрибутами `LogRecord` — это приводит к `KeyError: "Attempt to overwrite ..."`; требуется защититься от коллизий ключей.
* Мидлварь `asgi-correlation-id` берёт `X-Request-ID` (по умолчанию) и **валидирует как UUID**; невалидное значение отбрасывается и генерируется новый UUID. Нужно корректно «подхватывать» этот ID в логах.
* OWASP рекомендует: структурные логи, минимум чувствительных данных, корреляция событий и пригодность для SIEM. Это отражено в Top-10 A09/чите-шите

## Решение

Вводим небольшую надстройку над стандартным `logging`:

1. **JSON-форматтер** (`JsonFormatter`) — вывод в stdout одной строкой JSON: `ts, level, logger, message, …extra`.
2. **PII-фильтр** — маска `***` для ключей из denylist (`body`, `password`, `secret`, `token`, `note_body`).
3. **Correlation ID** — автоматически добавляется из `asgi_correlation_id.context.correlation_id` во все записи.
4. **Sanitizer extra-полей** — переименование конфликтных ключей `LogRecord` в `field_<name>` (например, `name → field_name`), чтобы не падать на `KeyError`. ([Stack Overflow][1])
5. **Удобный API** — класс `SafeLogger` с методами `.info/.warning/.error/.debug` и `.bind(**fields)` для «пришивания» постоянных полей.

## Детали реализации

* **Файл:** `utils_library/logger.py`

  * `JsonFormatter.format()` формирует базовые поля, подмешивает `extra`, добавляет `correlation_id`, применяет `_mask_pii()`, возвращает JSON-строку.
  * `_sanitize_extra()` переименовывает конфликтующие с `LogRecord` поля.
  * `setup_logging()` добавляет `StreamHandler(stdout)` с нашим форматтером для root-логгера (idempotent).
* **Инициализация:** `setup_logging()` вызывается в `app/main.py` при старте приложения; мидлварь `CorrelationIdMiddleware` подключена с заголовком `X-Request-ID`.
* **Использование:** в хэндлерах `notes`/`tags` добавлены точечные события (создание/чтение/обновление/удаление, листинги) **без PII**, только метаданные (`body_len`, `tags_count`, и т. п.).

### Пример записи

```json
{
  "ts":"2025-10-22T10:15:30.123Z",
  "level":"INFO",
  "logger":"app.routers.notes",
  "message":"note.created",
  "note_id":42,
  "title":"Intro to Graphs",
  "body_len":1280,
  "tags_count":2,
  "correlation_id":"8b8b6b39-42a4-4a7a-8d40-6b0f2cfa9f8c"
}
```

## Альтернативы, которые рассматривались

* **Оставить только `logging` без форматтера/PII-фильтра.**
  Отвергнуто: не выполняет NFR-03 (нет маскировки, нет единого формата).
* **Сторонние библиотеки (structlog/loguru).**
  Возможны, но усложняют стек; стандартного `logging` достаточно при наличии форматтера/санитайзера.

## Влияние

* **Плюсы:** единый JSON-формат, трассировка по `correlation_id`, соответствие OWASP A09, снижение риска утечек PII в логах, простые интеграционные точки. ([OWASP][3])
* **Минусы:** небольшая стоимость поддержки собственного модуля логирования; нужно держать denylist PII в актуальном состоянии.

## Тестирование и верификация

* **Юнит/интеграционные тесты:** `tests/test_logger.py`

  * Маскирование PII,
  * Sanitizer для reserved-keys (без `KeyError`),
  * Проверка формы JSON,
  * `correlation_id` пробрасывается при HTTP-запросе с UUID в `X-Request-ID`.
  * Примечание: дефолтный валидатор мидлвари принимает **UUID**, иначе заголовок будет отброшен и сгенерируется новый ID. ([PyPI][5])
* **Связка с NFR:** покрывает NFR-03 (0 утечек PII в логах, 100% записей с request/correlation-id; проверяется тестами + линтером логов в CI).

## План внедрения / миграции

1. Заменить точечные вызовы `logging` → `get_logger(__name__)` в коде API, не логируя PII.
2. Запустить тесты `test_logger.py`; добавить их в CI.


## Риски и как их снижаем

* **Риск**: разработчики случайно логируют PII.
  **Снижение**: denylist-маскирование на уровне форматтера; код-ревью; линтер логов в CI.
* **Риск**: падения из-за конфликтов `extra`.
  **Снижение**: sanitizer `_sanitize_extra()` переименовывает конфликтные ключи (известная особенность Python logging).
